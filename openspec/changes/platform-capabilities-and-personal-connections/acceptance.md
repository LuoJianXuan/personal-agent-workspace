## 2. 测试环境与数据

优先使用既有 5174 隔离栈、合成 MCP 和独立测试用户，不改公司仓库、不共用公司凭据。Mock 只替代模型输出；Backend、Runtime、PG、Tool Gateway、MCP SDK、审批均运行真实模块。

两用户隔离在合成 MCP 上完成：每个 Token 对应不同 canary 账户与工具目录，不能使用两份真实个人账户数据来证明隔离。秘密泄露检测用新生成 sentinel；不要把真实 Token 写入测试断言或结果文件。发现、授权本身不得调用 create-order/领券等业务工具。

只读测试可以写本项目测试会话/运行/结果；这些本地记录与外部写工具严格区分。真实麦当劳写工具只验证审批流程的本地合成等价场景，不实际创建订单、修改地址、领券或扣积分。

## 3. 真实联合验收建议窗口

建议在实施完成后单独确认：最多 8 次 DeepSeek 物理请求、每次最多 4096 输出 tokens、最多 4 次麦当劳只读业务工具调用；Tavily 新增真实请求 0，麦当劳真实写请求 0。初始化/发现次数单独记录，不用业务工具次数掩盖网络请求量。本段是建议额度，不是已获批准。

在准备进行真实验收时，先完成全部 Mock/隔离/浏览器连接流程和静态发布检查，再确认剩余真实窗口。失败重试计入总额度，额度不足停止真实调用并记录；不重置起始时间绕开已用次数。

首条任务从网页输入“请通过我的麦当劳连接查询当前月份的活动，并说明依据”；允许时间工具和活动工具。断言实际使用活动查询工具，不接受只调用 now-time-info 或模型凭知识回答。第二条额度预留给正式 5173/重建后复核，具体是否需要由证据决定，不反复请求模型只为截图。

没有明确身份归属授权时，不把现有部署 MCD_MCP_TOKEN 导入任意用户。用户可通过授权弹窗自行提供；本轮已明确授予测试身份使用该 Token 时才可按该授权执行。

## 4. 发布判定

发布必须同时满足：

1. 功能代码与共享契约完成，迁移重复执行无破坏；所有 PC 任务分别记录实现/验证状态。
2. 两用户身份隔离、审批、撤权、增量授权、秘密泄露和重建持久性全部通过。
3. 用户在网页完成一次个人连接与真实活动查询；管理员平台能力保持可用。
4. Langfuse 对同一真实 Run 有实际 observation，或者明确由用户接受本轮不启用观测；不能默认当通过。
5. 真实调用次数、费用保护、不可用能力和未执行项如实记录。Key、Token、Cookie、加密主密钥均不进入 Git 与证据。
6. 正式页面使用业务名称和恢复入口，不能把部署用配置名/堆栈报错当作主要用户提示。

发布报告必须给出：对应版本/变更范围、用户可完成的任务、各门槛结果、真实调用与 token 用量、trace 证据、运行配置是否持久、遗留项。无正式授权前不提交/推送 GitHub，不进行额外的公网写操作。
