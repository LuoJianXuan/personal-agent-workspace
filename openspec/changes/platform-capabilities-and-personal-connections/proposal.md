# 平台能力与个人连接：落地改造方案

日期：2026-11-16。状态：代码已接入隔离环境。浏览器连接和真实 MCP 只读验收通过，正式发布以 [任务清单](tasks.md) 的验证状态为准。

## 三个关键决策

1. **两种配置方式共存。** 模型、搜索、通用工具和平台 Skill 由管理员配置；麦当劳等个人账户由用户连接。划分依据是身份、数据归属和费用承担者，不是 MCP/Skill 的技术形式。
2. **连接级授权，操作级确认。** 用户一次授权当前连接的能力清单，普通查询可直接执行；写操作和风险未确认的操作执行前确认。默认不要求用户逐个开启工具，新工具与权限变化单独做增量授权。
3. **复用现有运行架构。** 保留 Go Backend、Python Runtime、DeepAgents、进程内 Tool Gateway 和现有 PostgreSQL；新增用户连接、加密凭证模块与契约，不新增常驻 Vault、MCP Proxy、Business Gateway 或新的 Agent loop。

## 用户任务与交付结果

| 任务 | 改造后的结果 |
| --- | --- |
| 直接提问、联网搜索、解析文档、生成报告 | 使用管理员提供的模型、搜索与执行环境，无需用户填写平台 Key |
| 点击麦当劳入口 | 弹窗填写个人 Token、发现能力、查看权限摘要、一次确认连接 |
| 问“麦当劳本月有哪些活动” | 已连接用户的 Agent 可使用活动工具，无需管理员逐工具开关 |
| 请求创建订单/兑换积分 | 展示具体操作及关键参数，用户确认后通过原审批链路执行 |
| A 与 B 分别连接麦当劳 | 各自凭据、发现结果、授权和调用独立；A 无法使用 B 的连接 |
| 使用管理员发布的“每日简报”等 Skill | Skill 可以组合平台能力与个人连接；缺少必需连接时提示连接，缺少可选连接时明确缺失部分 |
| Token 失效或断开连接 | 显示可操作原因；后续调用被拒绝，不回退到其他人的 Token |

“所有工具可用”指：当前发现、协议支持、用户已授权且未被平台明确禁止的工具都进入可用范围。普通查询可直接调用；其他工具可能需要执行确认。平台禁止项和不兼容 schema 必须显示原因，不能只说“仅支持一个工具”。

## 实施范围

- 预置一个个人连接器：麦当劳中国，固定 endpoint，Streamable HTTP + Bearer Token。
- 保留管理员配置的平台模型、Tavily、文档/沙箱能力、公共 MCP、通用 Skill。
- 每个用户每个连接器最多一个有效个人连接；平台/个人同名能力不自动切换账户。
- 个人凭据加密存储、换 Token、断开、重连、失效、增量授权、工具分类和执行审批。
- Skill 的依赖声明与就绪状态；不重做现有 Skill 加载机制。
- 正式部署配置持久化核对，包括真实模型预算、Tavily、Langfuse、凭据加密主密钥；额度不自动扩大。

## 非目标

本轮不做开放连接器商城、任意 URL/Header 输入、OAuth 全流程、stdio、本地桌面桥接、legacy SSE、用户自制连接器、多账户切换、企业共享权限体系、个人 Skill 编辑器、长期记忆、自动化或向量化工具检索。OAuth 只在数据模型预留认证类型，不创建假可用入口。

## 对旧方案的明确调整

- 保留部署级 `credential_ref` 供平台能力使用，新增个人凭据引用；不把平台 Key 全部迁入个人凭据库。
- 个人预置连接器采用批量授权；管理员逐工具开关保留为平台连接与紧急禁用能力。
- 不再把个人连接器中所有未列工具永久设为 blocked：兼容且未明确禁止的未知工具，在用户授权清单后可进入“每次确认”路径，不能凭名字或模型推断自动标为只读。
- 工具风险分类与原始 `readOnlyHint` 分开存储；服务提示不能直接扩大权限。
- 该变更获准实施后，替代旧 `mcp-1-1-and-workbench-baseline` 中仅限部署凭据、未知工具必定 blocked 的个人连接部分。旧验收作为历史保留，不改写为新方案已完成。
