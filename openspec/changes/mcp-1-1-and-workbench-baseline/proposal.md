# MCP 1.1 与工作台交互基线

## 背景

第一阶段只开放部署清单中的只读 MCP，写工具无法进入能力快照；前端又把一次工具调用拆成 requested/started/completed 多块展示。进入第二阶段前，需要先补齐真实远程 MCP 的分级准入、逐次审批和可理解的状态展示。

## 目标

- 继续以进程内 Tool Gateway 为唯一 Agent 工具准入边界。
- 远端服务声明只作提示，部署清单才是 read/write/blocked 的权威分类。
- MCP 写工具可以被管理员启用，但每次执行必须绑定 Run、执行 ID、参数哈希、快照和审批决定。
- 远端调用具备固定目标、凭据引用、进程级超时、取消、结果限长、每连接速率限制和 UNKNOWN 收敛。
- 工作台把一次工具调用合并为一张状态卡，并提供个人能力设置入口。

## 非目标

- 不开放任意 stdio 命令、OAuth、MCP 商城或共享企业连接器。
- 不自动信任服务端 `readOnlyHint`。
- 不调用麦当劳下单、地址、领券或积分兑换等真实写工具。
- 不引入独立 Tool Gateway 微服务。

## 完成结果

麦当劳中国 Streamable HTTP MCP 已通过真实发现和只读调用；未知新增工具保持 blocked。通用 MCP 写工具通过本地合成服务完成审批暂停、批准恢复和一次性执行验收。

2026-11-16 起，用户自带 Token 的个人连接适用 [平台能力与个人连接方案](../platform-capabilities-and-personal-connections/proposal.md)，自然人账户凭据按用户授权，兼容且允许的未知风险工具逐次确认。平台 MCP 沿用本变更的部署准入机制。
