# S19 — Agent 级 Langfuse

状态：代码齐备；独立 Project/Key 真实本机入库和故障旁路验证通过。日期：2026-11-06。

Runtime 锁定 Langfuse Python SDK 4.x，使用官方 `langfuse.langchain.CallbackHandler` 挂入 DeepAgents graph config。稳定 trace 由 run_id 派生，thread 作为 session；只采集 Agent/模型/工具回调。观测副本脱敏并限长，关闭时有界 flush；配置缺失直接旁路，运行详情只接收服务端生成的受控 URL。`LANGFUSE_PUBLIC_URL` 与容器内 ingest URL 分离。

本机既有 Langfuse v4 已使用原 `langfuse.env` 恢复，PostgreSQL、Redis、ClickHouse、MinIO、worker、web 均健康。新建 `Personal Agent Demo` 项目和专用 Key，与 `kefu-cs` 各自仅有一套 Key，未复用或写入另一项目。bootstrap secret 已从 Langfuse Web 容器移除；专用 Key 只保留在当前隔离 Runtime 容器环境，仓库扫描未发现生成值。

实际运行 `mock:tool` 后，通过 Langfuse v4 Observations API 查询到同一稳定 trace 的 18 个 observation，类型含 `AGENT / CHAIN / GENERATION / TOOL`，名称含主 Agent、MockChatModel 与真实 MCP 工具；导出结果不含 secret。最初使用已废弃 `/api/public/traces` 在 v4 `events_only` 模式返回 404，已改为官方 `/api/public/v2/observations` 并复验通过。隔离 Runtime 指向不可达地址后，真实 Agent→模型 Mock→MCP 工具仍成功，稳定 trace URL 被投影，秘密未进入 canonical events；最终代码复验耗时 8.927 秒且无未捕获错误。

获得本轮 12 次物理请求、每次最多 4096 输出 token 的明确授权后，隔离环境使用正常配置完成两条真实 DeepSeek 任务：第一条由模型调用 `builtin_read_material`，触发 DOCX 按需解析并准确回答项目代号与预算；第二条由模型调用真实只读 MCP 查询合成订单。两条 Run 均成功，共 4 次供应商请求，21,326 input tokens、183 output tokens（其中 10,368 input tokens 命中缓存）。每条稳定 trace 都从 Langfuse v4 查询到 `AGENT / CHAIN / GENERATION / TOOL`，工具名分别为文档工具和 MCP 工具。

运行详情浏览器实际展示了稳定 run id、模式和服务端受控“查看 Agent 调用”链接；该链接存在不等于 trace 已入库。
