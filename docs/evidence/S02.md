## 验收中发现并修复

1. MCP 1.9.3 实际导入时依赖 Pydantic 的内部接口，新版不兼容；固定 pydantic 2.11.7 / pydantic-settings 2.9.1 并重新生成 uv.lock，真实发现复验成功。依据 SDK 与 Pydantic 对应版本源码核对，未凭空升级 SDK。
2. SDK 面对静默服务时可能卡在取消清理阶段。发现放入 Runtime 启动的短时工作进程，最多并发 4 个、总时限 6 秒，到期终止并等待回收；不新增部署服务，不影响 Runtime 的持久状态边界。强制超时和真实发现均复验。
3. MCP endpoint 使用确切 `/mcp/` 路径，避免 SDK 默认重定向行为；自定义 HTTP client 禁止重定向及环境代理，已验证不会请求重定向目的地。

## 一条请求与失败点

管理员创建 MCP → Runtime 真实发现 → Backend 保存工具、默认禁用 → 管理员明确启用 → 用户 catalog 可见 → Backend 解析并保存快照 → 内部 validate 复核 owner、用户和配置 revision。

失败点：技能/模型/工具/MCP 已禁用或版本改变，旧快照复核返回 allow=false；新解析不静默丢弃显式选定的失效技能或换模型。
