## 真实改动与接口
- Web：src/main.tsx、api.ts、style.css，/login、/app/chat、/app/profile、/admin、/admin/users；真实 login/me/users、公共错误、loading/empty、角色守卫、移动抽屉与退出。
- Backend：POST /api/auth/login、GET /api/auth/me、GET /api/admin/users、GET /health、GET /ready、带反向令牌的 /internal/health。bcrypt cost=12；JWT HS256 issuer/audience/exp、8 小时默认有效期；每请求查 enabled。用户名/密码失败统一 401，普通用户管理 403，数据库错误不冒充密码错误。
- workspace.Service.OwnedThread 按 tenant/project/owner 联合过滤；agententry 定义应用接口与 RuntimeClient、独立普通 RPC/SSE 连接池。不提前实现 S03 派发。
- Backend 001_foundation.sql 创建 users/threads/schema_migrations；显式 migrate 命令、事务 advisory lock，无启动 AutoMigrate。seed 从项目环境读取三账号，ON CONFLICT DO NOTHING 不覆盖旧密码。
- Runtime：FastAPI lifespan AsyncConnectionPool，方向服务令牌检查，/internal/health 与 /internal/ready；ready 核对业务迁移和完整 checkpoint migration 版本。app/migrate.py 显式 AsyncPostgresSaver.setup，不在请求中建表。
- deploy/postgres/init.sh 建立两个独立非超级用户角色、私有 schema 并移除 public CREATE；Compose 仅 Backend 挂文件卷，仅 Web localhost 暴露。
- compose.yaml 五服务定义，demo-mcp 处于未就绪 profile；scripts/dev.ps1、migrate.ps1、seed.ps1 与 Makefile；隔离 .env.test.example；scripts/init-env.ps1 生成独立随机秘密且拒绝覆盖。

## 预期请求链与失败
Web login → Backend JSON Schema → PostgreSQL + bcrypt → 有效期 JWT → me 每次查 enabled → 选择布局。普通用户直接请求管理 API 403；禁用用户旧 token 401。Runtime 拒绝浏览器 JWT；缺迁移或 checkpoint 初始化不完整 ready 503。
