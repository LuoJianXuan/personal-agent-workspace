## 1. 交付目标与范围

第一阶段完成后，用户应能通过同一个对话入口完成三类真实任务：

1. **网页研究：** 搜索一个主题，读取多个来源，形成有可定位引用、可下载的研究报告。
2. **材料比较：** 上传两份文字型 PDF/DOCX，比较变化和风险，输出报告，并能在同一会话中修改为新版本。
3. **数据处理：** 上传 CSV/XLSX，完成受控统计或 Python 加工，得到可核查数据、图表与报告。

共同要求：过程可见、权限可控、失败有结果、刷新不重跑、原件不被覆盖；所有实际产物都能经鉴权下载。

### 1.1 三个实施决策

1. **按 A/B/C 批次交付。** A 是 Harness + 网页研究 + 首页体验；B 是文档与上下文；C 是计算与正式产物。A 完成不能宣称整个第一阶段完成。下一轮 5–7 天窗口仅安排 A；B/C 开始前按实际依赖冻结各自窗口，不把所有内容挤入同一个 7 天承诺。
2. **升级执行底座，沿用服务边界。** Web、Go Backend、Python Runtime 保持独立。DeepAgents 接入现有模型适配、逻辑 ToolGatewayService、审批、规范事件与外置状态；不直接把框架示例替换整个产品链路。
3. **以任务结果判定交付。** 安装依赖、出现按钮、Mock 返回文字都不等于完成。代码齐备、隔离环境运行通过、真实服务验证通过分别记录；测试/付费请求只有获得相应授权后才执行。

### 1.2 范围矩阵

| 能力 | A 必须 | B 必须 | C 必须 | 明确后置 |
| --- | --- | --- | --- | --- |
| Harness | 主 Agent、模型桥接、工具桥接、规范事件、基础步骤 | 长结果外置与摘要恢复 | 执行 worker 接入 | 子代理与多 Agent |
| 网页 | 真实搜索接口、公开网页读取、引用 | 复用 | 复用 | 登录态、验证码、通用浏览器接管、爬虫平台 |
| 文件 | 现有 TXT/MD/CSV 不退化 | 文字型 PDF/DOCX、分段检索、工作文件与最小版本链 | XLSX 基础读取 | OCR、旧 DOC/XLS、宏、完整版式还原 |
| 计算 | 现有固定 CSV 聚合 | 复用 | 固定计算 + 受隔离的 Python | 任意主机命令、运行第三方项目、在线 pip 安装 |
| 产物 | Markdown 报告、引用清单 | 报告新版本、来源定位 | DOCX、汇总 CSV、图表 JSON | PDF/PPTX 导出、实时协同编辑 |
| UI | 首页输入框、真实任务卡、会话查找、过程/来源/产物 | 文件状态、引用定位、版本选择 | 计算状态、表格/图表、正式下载 | 记忆、项目、自动化的不可用入口 |
| 个人化 | 保留现有技能与偏好 | 保留 | 保留 | 项目空间、长期记忆、个人技能编辑，属于 P2 |

## 3. 架构、所有权与执行边界

| 层 | 本阶段职责 | 不应承担 |
| --- | --- | --- |
| Web | 输入、文件选择、步骤/工具/引用/产物展示、审批和取消 | 工具权限判断、任意 URL 代理、计算真相 |
| Backend/control | 模型/工具配置、授权、凭据别名元数据、revision、能力快照 | Agent loop、保存另一份 Run 状态 |
| Backend/workspace | 会话/提交、文件与衍生物、工作文件版本、解析任务、审批决定 | 执行模型、读取 Runtime 的表 |
| Backend/agententry | API 聚合、内部路由、SSE/来源投影、任务提交 | 沉淀新的控制面事实或独立执行工具 |
| Runtime | Harness、模型请求、运行状态、工具执行记录、来源记录、规范事件/checkpoint | 长期记忆或配置权威、直接读 Backend 文件卷 |
| ToolGatewayService | 快照、工具名/参数/作用域、审批、限额、目标地址与执行裁决 | 绕过 Backend 权限、把框架默认工具全部放开 |
| 文档 worker（B） | 解析/格式转换，无模型调用；仅处理租约任务的输入 | 任意代码、读取整个文件卷、直接写控制面数据库 |
| 计算执行层（C） | 受限输入上的一次计算及输出回收 | 业务凭据、宿主机访问、持久用户资料 |

Backend 和 Runtime 继续使用各自 PG schema/数据库角色。新增表各归其域，无跨 schema JOIN，不改其他本机项目的 PostgreSQL。

框架内建文件工具必须使用自定义作用域 backend；默认 shell、宿主文件 backend、自动记忆写入和子代理在 A/B 关闭。框架内部计划更新不等于外部业务工具执行，但仍要有可重建的步骤事件。

用户的“允许联网”和工具选择只能缩小 Backend 已授权能力，不能自行授予权限；有效工具与网络策略在提交时由服务端冻结，执行前复核 revision。

所有凭据只在受信执行边界解析；不放入 Start、LangGraph state、规范事件、工具结果、模型消息或 trace。禁用未配置的框架外部 tracing，避免升级依赖后自动上传上下文。

### 4.2 API 与事件

- 沿用现有提交、取消、审批、查询、SSE 和文件下载入口，不让 Web 直连 Runtime。
- 新增来源查询/引用定位、文件解析状态/分段读取、工作文件版本、二进制产物提交等契约；路径在 OpenAPI 冻结，不把下面的概念名当作现存 API。
- 原内部文件 content 接口目前返回文本；B/C 单独增加带作用域的二进制流接口。PDF/DOCX/XLSX 不转换成乱码字符串，也不把大段 base64 放入 checkpoint。
- 新增步骤变化、来源就绪、上下文压缩等规范事件；保留现有 Run、message、tool、approval、artifact 语义。最终正文仍以同一 message_id 收敛，不重复插入。
- 事件升级先更新消费者；增加明确版本处理，不向旧记录回填虚构事件。步骤状态不替代 Run 状态，也不新增一套后台“任务成功”事实。
- 工具结果输出统一保留成功/可恢复错误/终止错误分类、文本摘要、来源与文件引用，不能只返回无结构字符串。
- 对带引用的报告，发布前核查引用 ID 与实际读取范围；不存在的引用拒绝发布并给出可修订错误。引用存在不代表结论必然正确，语义支持仍属于验收检查。

## 5. A 批次：S08–S11，目标 5–7 天

### S08：契约、依赖和迁移基线

**前置：** 读取现有接口、最新回归和锁文件。

**执行顺序：**

1. 固定当前构建/镜像标识和数据结构；盘点 QUEUED/RUNNING/WAITING_APPROVAL，只有确认授权环境才读取实际状态。生成无秘密清单。
2. 核对候选 DeepAgents、LangChain、LangGraph、checkpointer 和 Python 3.13 依赖；记录选定组合、官方依据与替换的旧约束。同步产出“采用框架/删除旧实现/必须保留的业务规则”矩阵。锁文件求解属于实现准备，不能作为运行通过。
3. 冻结第 4 节 A 所需对象、事件、限额、错误和兼容样例；列出 B/C 扩展点但不提前添加不可用枚举。
4. 设计引擎版本和迁移。默认采用切换前排空旧运行：旧等待审批的任务由旧引擎处理至终态；需要放弃时显式取消/结束，不静默改为新引擎。
5. 新引擎使用新 checkpoint namespace；若框架升级涉及共享 saver 表结构，采用独立的 Runtime 存储 namespace/schema，禁止对旧 saver 原地升级后声称可回滚。
6. 明确首个真实搜索 provider。默认 Tavily；只保存目标地址、凭据别名和参数范围，密钥由部署环境注入。

**结果：** 兼容矩阵、共享契约、迁移/回滚清单、搜索依赖清单、准备好的验证入口设计。若依赖组合无法满足桥接要求，此 Spec 标“需修复”，后续不假定 Harness 可用。

### S09：Harness、模型、工具与事件接入

**前置：** S08 的契约与依赖组合确定。

1. 将 Engine 收敛为生命周期协调层；创建实际 DeepAgents 主 Agent，删除旧 model/prepare/approval/execute/merge 通用图循环，不保留第二套工具编排。
2. 协议配置优先构建标准 LangChain ChatModel；由标准集成处理消息、tool_call_id、流式片段与 usage，自有代码只负责配置/规则和必要的归一化。核对后移除可被替代的供应商 SSE 解析与工具参数拼装，不默认把旧 models.py 整体包成自定义模型。provider 标签不参与适配器分派。
3. 调用次数限制优先采用官方 ModelCallLimitMiddleware/ToolCallLimitMiddleware；在实际传输边界统一保障真实请求额度，包括自动重试、摘要和辅助调用。关闭隐藏 SDK 自动重试，或统一接管并计数。保存 attempt 与用途，不把多个物理请求算作一次；核对审批恢复后的计数范围。
4. 把原 3 个内置工具和授权 MCP 经 ToolGatewayService 注册到 Harness。按照本轮快照构建工具目录；不暴露未注册默认工具。
   A 只使用既有资料读取和新报告发布接口；在 S12 的作用域文件 backend 就绪前，关闭依赖通用工作文件的默认文件工具、自动结果外置和自动摘要。构建后检查实际模型可见工具清单，不以“没有传入工具”推断框架未注入默认工具。
5. 把现有工单专用审批判断整理为显式策略映射，但工单参数/唯一执行 ID/对账链路不变。新 A 工具只读网络；发布本 Run 自有报告按确定范围处理，不获得外部事务权限。
6. 使用官方 HITL/interrupt_on 与 checkpointer，移除旧 approval 图节点和重复恢复机制；将框架提案映射至既有审批入口，Backend 继续做 owner/有效期/参数绑定校验并保存决定。一次批准只驱动一次规范化恢复，工具执行前再次复核业务规则。一轮工具串行执行，保持一个对外待审批点。
   每个工具只选一个审批裁决来源。首批简单工具优先官方 HITL；若未来由工具策略层返回 approval_required，则用薄中间件接入同一 LangGraph 中断基础，不同时对该工具配置重复 interrupt_on。不能为模仿公司架构而预先实现两套审批路径。
7. 流事件经过桥接生成规范事件，保持正文增量、最终去重、顺序与补读；内部参数碎片和隐藏推理不显示。
8. 基础步骤持久化，简单聊天不强制列计划。取消在模型前、工具前和输出发布前检查；等待审批释放执行槽。
9. 可恢复的来源超时/空结果返回有结构的工具失败，允许有限改查；权限/配置失效、预算耗尽和取消终止执行。不能让一个可跳过网页错误直接毁掉整项研究，也不能吞掉权限拒绝。

**结果：** 通用聊天、MCP、工单审批、CSV、取消/断线/历史都能通过新主 Agent 管线；尚未经授权验收时只标代码齐备。

### S10：网页研究与可核查报告

**前置：** S09 可接入受控工具。

新增工具的预定最小契约：

| 工具 | 输入 | 输出 | 边界 |
| --- | --- | --- | --- |
| builtin_web_search | query、受限 max_results | 结果标题/URL/摘要、source_id、实际查询时间 | 首个 provider 固定 REST 接口，不接受用户提供任意搜索 API 地址或凭据 |
| builtin_fetch_page | 公开 URL 或已发现 source_id | 实际最终 URL、段落、hash、读取时间、截断状态 | 只读公开网页，不携带浏览器 cookies；每次跳转重新准入 |
| builtin_publish_report | 标题、Markdown、真实 citation 列表 | Backend READY 文件引用 | 只发布本 Run 的自有 Markdown；相同 execution_id 幂等，不覆盖原件 |

**实施：**

1. 搜索默认 basic、关闭供应商生成答案/图片/自动扩展参数，结果转换为统一 SourceRecord；不让搜索供应商的答案替代实际阅读与本模型任务。
2. 抓取只接受允许的 HTTP(S) 公开地址、标准端口；校验 DNS 结果并保证连接使用经过校验的地址，每次重定向重做校验，阻断 loopback、私网、链路本地、元数据地址及 IPv4/IPv6 变体。不通过任意代理环境绕过。
3. HTML 提取正文、去脚本/样式，保留标题/段落定位。首版不执行网页 JavaScript。认证、付费墙、403、动态空白页显示无法读取。
4. 搜索摘要与已抓取正文区分来源状态。报告关键结论引用实际读取片段；只看到摘要时明确说明证据不足，不声称读过全文。
5. 来源记录落 Runtime 自有域，按 owner/run 查询；报告字节经内部作用域 API 由 Backend 存储。下载前鉴权，预览禁止原始 HTML 和危险链接。
6. 旧导出 report.md 的终态约束保持原语义。新运行内报告使用独立的产物键与能力规则，不能为了发布中间报告放开全部 InternalArtifact 校验。
7. 发布报告可以在模型最终答复前完成；随后模型失败时保留已就绪文件、将 Run 标失败，页面展示“已有产物，任务未完成”，不能用文件存在冒充 Run 成功。

**结果：** 从普通对话完成搜索→阅读→组织→发布，报告的来源表可打开、可定位，真实搜索未接通时明确未完成真实研究验收。

### S11：UI 集成、A 批次验收与发布准备

**前置：** S09/S10 的可展示契约固定。

1. 首页采用欢迎语、中央输入框、真实任务卡；已有会话保持底部输入框。未配置搜索时研究卡显示缺少连接，不产生假任务。

3. 对话中展示步骤、工具状态、来源和产物，默认折叠详细技术信息；模型和附件配置保留清晰入口。

## 6. B 批次：S12–S13，文档和上下文

### S12：文档输入、工作文件和最小版本链

**前置：** A 达到已约定的兼容/验收门槛，二进制和解析契约冻结。

1. 增加 PDF/DOCX 上传格式识别、原件存储与解析任务；先接 Backend 事务与内部流，再接解析 worker，最后接 Web 状态。扩展名不作为唯一判断。
2. 文档 worker 使用可信固定程序、无模型调用、每任务独立子进程和资源/时限；仅通过租约与作用域 API 获取原件，向 Backend 提交解析结果，不直连业务表。
3. PDF 保存物理页号和段落定位，说明物理页号不一定等于文档印刷页码。DOCX 保存段落/表格单元格定位，不伪造渲染页码。混合扫描内容须列出未提取页，不能无提示丢弃。
4. 对加密、损坏、扫描件、超限和未支持结构返回明确状态；原件仍可下载。ZIP/XML 格式检查解包后大小、条目、外部关系和 XML 资源限制。
5. 扩展 read_material 支持段落/页区间、截断与定位，新增材料内关键词检索；仅访问本轮授权 file_id/hash。未解析好返回 NOT_READY，不以空文本当成功。
6. 工作文件仅支持逻辑路径 /inputs（只读引用）、/work（临时工作）、/outputs（待发布）。禁止绝对宿主路径、..、符号链接越界和覆盖输入文件。
7. Backend 保存不可变文件版本。用户要求“修改刚才报告”时，后续 Run 由入口重新授权所选旧产物；新版本通过 parent_file_id 关联，不因存在于会话就允许读取所有历史文件。
8. 仅交付查看版本、选择版本继续处理的最小闭环；项目级资产管理、任意文档差异编辑属于 P2。

**结果：** 两份真实文字材料能比较、有页/段落依据并生成 v1；用户修改后生成 v2，v1 和原件保持可下载。

### S13：长结果外置与上下文压缩

**前置：** 可用的工作文件/引用接口，S09 预算与事件可复用。

1. 统一上下文预算单位。模型 context_limit 明确按 token；准确 tokenizer 可用时使用，否则采用标明估算的保守策略，不能再将 UTF-8 字节与输出 token 直接相加。
2. 工具大结果保存到受限工作文件，返回摘要、范围、hash 和可继续读取的引用；不能无提示截断关键材料。
3. 使用官方摘要/外置中间件按输入预算阈值处理，不再自建第二套压缩循环；配置保留最新明确需求、约束、文件/来源引用、步骤和已执行动作，完整历史不删除。待审批参数与执行幂等证据不依赖摘要重建。
4. 摘要调用也走同一模型适配器、权限和全局预算，保持用途可见。摘要失败只能采用确定性缩减/停止并提示，不能绕过限制或悄悄多调模型。
5. 外置内容及摘要绑定 run/thread、来源范围与版本，恢复时重新校验权限；不是个人长期记忆，不自动跨会话检索。
6. 记录 context.compacted 的摘要范围/统计和版本，UI 只提示上下文整理，不显示隐藏推理。历史摘要和外置文件生命周期有可执行清理规则。

**结果：** 较长材料、多轮修改仍能保持任务约束；达到限制时错误清楚，已有产物和审批事实不丢失。不承诺无限上下文或任意断点恢复。

## 7. C 批次：S14–S15，计算与正式产物

### S14：计算执行边界、XLSX 与 Python

**前置：** 文件输入输出/版本和执行记录已稳定。先做隔离，再注册动态 Python 工具。

1. 固定 CSV 统计继续使用现有确定性 Decimal 程序；自然语言转为受校验参数。用户未指定单位、空值/重复值/日期口径不明确时询问或显式声明口径，不默认编造。
2. 增加 XLSX 单工作表/指定表读取，限制解包体积、表/行/列/单元格数；不支持 XLS/XLSM、宏、外部链接和 Excel 公式重算。公式仅在有可用缓存值时读取并标注来源，无缓存明确缺失，不置零。
3. 计算任务只包含代码、授权输入清单和输出约定；身份、模型或连接凭据不进入执行环境。
4. 本地 Docker 的候选执行方式是可信 launcher 创建一次性 job 容器：固定镜像、禁网、非 root、只读根、受限临时目录、drop capabilities/no-new-privileges、CPU/内存/PID/时间限制；输入输出通过受控复制，不绑定宿主文件目录。
5. 若采用拥有 Docker 控制权的 launcher，必须单独评审其受信权限和部署方式。它仅接受固定模板任务，不能接收模型指定镜像、挂载、网络或 Docker 参数；模型代码、Runtime 和 job 容器均不得持有 Docker socket。不能用一个持久 Runtime 容器中的普通 subprocess 冒充隔离沙箱。
6. launcher 配置/授权未满足时，动态 Python 工具不注册；固定计算仍可交付，但 S14 的动态执行结果标“未完成”。若要改用托管沙箱，先冻结费用、数据出境和凭据方案，不自动切换。
7. 固定依赖离线构建，不在运行中安装包；代码执行失败/超时输出安全错误与有界日志。AST/导入过滤仅作附加限制，不能作为唯一隔离措施。
8. 发布前验证输出文件数量、大小、类型、路径和符号链接；结果文件经 Backend 存储，job 销毁。取消后终止本次 job；broker/Runtime 重启后按 execution_id 清理或对账，不自动重复执行未知任务。

**结果：** 在有限格式/依赖/资源内完成计算，并证明越界读取、联网、超时、取消和输出回收的行为。隔离失败即阻止开放该能力。

### S15：正式报告、图表接入和第一阶段交付

**前置：** A/B 产物和 C 计算链路齐备。

1. 以已验证结构化内容生成 DOCX：标题、段落、列表、表格、来源表；不承诺复杂模板还原、复杂公式或 PPT。用户下载后能打开且中文可读。
2. 汇总 CSV 与受校验 chart JSON 由程序生成，图表绑定实际输入文件和口径。模型负责说明，不修改计算数值；避免 CSV 内容被无意解释为可执行公式。
3. 终态后的纯格式导出尽可能从已保存内容生成，不额外调用模型。新增内容/修改内容必须是用户发起的新 Run，不通过 GET 下载隐式执行。
4. 产物 generation 状态与文件 READY、Run 终态分别显示；导出失败可重试同一幂等操作，不重新生成整轮回答。跨 Run 版本关系由 Backend 验证归属。
5. 完成文档/计算/报告 UI、失败态和移动端；保留原 CSV 页面并复用同一能力，不做独立场景平台重构。
6. 准备并按授权执行第一阶段总验收；交付范围、证据、限额、依赖、迁移/回滚和已知限制。只有所有必需任务通过才称 P1 完成。

**结果：** 用户可以交付网页研究、材料比较、数据处理三个任务，并拿到实际可用文件；功能和限制均有对应证据。

## 8. 建议默认限制与失败语义

下表是初版实现目标，S08 按实测冻结；不是性能测试结论，也不是实际调用授权。用户界面不必展示全部技术参数，但触及限制时须说明。

| 项目 | 初始值/规则 |
| --- | --- |
| 单 Run 模型调用 | 最多 12 次物理请求，包括摘要、重试；部署/授权总额度可更低 |
| 每次输出 | min(模型配置上限、部署上限、本次授权上限)；无新增授权则不发真实请求 |
| 工具调用 | 最多 20 次；A 一次研究最多 2 次搜索、每次最多 5 条结果、最多读取 6 个页面 |
| 网络超时 | 每请求总计 20 秒、最多 3 次跳转；跳转不重置总时限 |
| 单网页 | 下载/解压各有上限，初始 2 MiB；最多返回约 20,000 中文字符，截断可见 |
| Run 执行 | 活跃执行累计 180 秒初始目标；审批等待暂停计时，恢复沿用剩余预算；不承诺无限续跑 |
| 附件 | 先保留单文件 5 MiB；单 Run 最多 5 份，扩大前单独核对解析资源 |
| 文档 | 初始最多 100 物理页/5,000 段落、解析 30 秒、512 MiB；超过或部分提取明确提示 |
| XLSX | 初始 10 张表、每任务最多 100,000 个单元格；只处理明确选择的工作表 |
| Python | 初始 1 CPU/512 MiB/64 PID/30 秒、默认无网络；每次 job 独立临时目录 |
| Python 输出 | 最多 5 文件/合计 10 MiB，单文件仍受 Backend 文件限额；stdout/stderr 各 64 KiB |
| 并发 | 不提高现有 4 Run/32 队列承诺；新 worker 初始串行，不以配置值声称吞吐能力 |

预算在发起实际请求前原子预留；刷新、重连、重复提交、审批恢复不重置本 Run 的累计次数或时长。安全网络重试至多一次且占工具/网络额度；模型与动态计算不做不可见自动重试。

| 场景 | 必须呈现的结果 |
| --- | --- |
| 搜索未配置/额度不足 | 联网研究不可用；不切 Mock、不编造来源 |
| 一页超时/无法读取 | 该来源失败，可换其他来源；达不到用户要求时说明不足 |
| 越权文件/禁用工具/快照变化 | 不执行；给出拒绝或配置失效，不自动扩权 |
| 无法满足必需结果 | Run 失败/未完成，保留已有文件与草稿；不新增含糊的“成功但其实没做”状态 |
| 允许部分交付 | 明确列出完成/未完成项；不把步骤或文件 READY 当全任务成功依据 |
| 文档扫描/损坏/加密 | unsupported/failed 与可解释原因，原件仍可下载 |
| 引用不存在/不在读取范围 | 报告发布拒绝，允许有限修订；不能生成伪造引用 |
| 摘要或预算失败 | 停止额外调用并保留现有结果，说明限制 |
| 报告发布响应丢失 | 用 execution_id/产物键查询同一结果；不产生重复文件 |
| Python 超时/取消/异常输出 | job 被终止/回收，非法输出不发布，其他用户数据不暴露 |
| Runtime 重启 | 已完成历史可读；确认的审批点按版本恢复，其他状态按既有 INTERRUPTED 边界；不承诺任意断点续跑 |

### 9.2 验证分层

1. **静态核对：** 契约、引用、依赖锁与源码边界。可按项目规则执行，不算测试通过。
2. **授权后的隔离验证：** Mock 只替换模型，网页 fixture 是明确标记的测试上游；数据库/MCP/审批/文件/计算必须走真实模块。网页 fixture 不能作为真实联网成功证据。
3. **授权后的真实验证：** 单独记录模型物理请求数、输出限制、搜索服务实际请求和预算；使用固定公开任务与无敏感材料。不开启不受限的自动重试。
4. **授权后的浏览器业务验收：** 实际点击、上传、下载和移动端，接口成功不替代 UI 验收。旧授权不自动等于这次新增验收授权。

沿用已有 make contracts、make build 和 scripts/verify-mock.ps1；新增验收脚本由各 Spec 实现并接入统一入口。现有 verify-mock 在明确授权后使用 -Authorized；本规划不运行这些命令，也不把尚不存在的新脚本写成已经可用。

### 9.3 批次状态与上线规则

- **代码齐备：** 所有消费者接入、无假数据/TODO 冒充能力，提供验证入口。
- **隔离验收通过：** 对应 Mock/故障/权限/恢复/浏览器用例按授权实际通过。
- **真实能力已验证：** 真实搜索与模型对应任务通过；未执行明确标出，不用 Mock 结论补齐。
- **可切换日常环境：** 已满足迁移、回归、版本绑定与回滚要求；只更新本项目，保留卷和旧镜像，不执行 down -v，不改宿主其他数据库。
- **第一阶段完成：** S08–S15 全部必须结果达标，三类真实任务可交付，动态计算隔离与下载文件有证据。少任何一项均按实际批次报告，不把 A 说成 P1。

每个 Spec 输出 docs/evidence/SXX.md，包含：输入/变更、契约与迁移、成功/失败链路、实际证据、未执行项、限制与下一接入点。最末提供依赖/配置说明、启动步骤和回滚演示记录。

## 10. 一条任务链路与一个关键失败点

以“研究三种方案并输出比较报告”为例：

```text
用户发送目标并选择允许联网
  → Backend 认证、解析授权与工具快照、保存 submission
  → Runtime 接受同一 run_id、绑定引擎/预算
  → DeepAgents 计划任务
  → ToolGateway 准入搜索、读取网页并保存来源
  → 模型依据实际来源整理内容
  → ToolGateway 校验引用与发布范围
  → Backend 幂等存储报告，返回 READY 文件
  → Runtime 产物事件/最终回答/终态
  → Backend 投影与 SSE → Web 来源和下载入口
```

关键失败点：报告文件已经保存，但发布响应丢失。处理方式是按稳定执行 ID/产物键查询并复用同一文件；如果后续模型调用失败，保留文件并显示任务未完成。不得重新发起一整轮任务、重复发布，或只因文件存在就标 Run 成功。
