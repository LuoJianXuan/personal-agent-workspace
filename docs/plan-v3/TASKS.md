## 每个 Spec 的执行顺序

1. 确认前置状态与对应环境，不用公司项目替代缺失模块。
2. 冻结本 Spec 范围、输入输出、作用域、失败语义与所需外部依赖。
3. 跨层修改先更新 schemas/OpenAPI/JSON Schema/样例，再生成并接入 Go/Python/TS。
4. 完成全部消费者与 UI，准备验证入口和数据；不能只交空壳。
5. 按会话授权执行检查；未授权的测试、浏览器与真实请求保持未执行。真实额度按本次授权统计，不复用旧额度。
6. 写 docs/evidence/SXX.md，更新本表的实现/验证两列；说明限制、未执行项和下一任务接入点。

每个 Spec 的详细步骤、变更位置、完成条件在 PHASE1-EXECUTION.md 第 5–7 节。每个 Spec 都要能追踪一条实际请求与一个失败点。
