# 实施规则

1. 期限固定 5–7 天；AI 写全部代码，用户不需手写，不额外排数周学习。
2. 每次按当前 Spec 实现并接入已完成模块；不得只交骨架/TODO 却标完成。依赖未完成时准确记录。
3. 不主动使用子代理。用户明确要求并行时才另行分工。
4. 独立个人项目，禁止未经明确范围授权复制公司资产；不改 C:/MyWorkSpace/lingji-ai 当前实现。参考网站账号密码不得写进任务包、代码或 seed。
5. Web/Backend/Runtime 必须独立职责与进程；不能为了赶工合并 Backend/Runtime。
6. 默认不运行测试、浏览器自动化测试或真实模型调用。AI 准备验证入口；用户/CI 或后续明确授权执行。代码阅读、文档链接核对、静态差异检查可继续。
7. 已授权实现时，安装依赖、本项目隔离开发库迁移、本地服务启动按工具权限执行，无需逐项重复询问；不接公司环境。测试偏好仍单独适用。
8. 真实模型调用次数与预算由用户授权；Mock 只替换模型输出，MCP/数据库/审批/文件必须走真实模块。
9. 秘密不入文件、快照、checkpoint、事件、模型上下文。各服务只写自己的数据域。
10. 不将普通配置页面称为完整企业治理平台；范围与失败要可见。
11. 每个 Spec 输出 docs/evidence/SXX.md：改动、契约、预期成功/失败调用链、已执行证据、未执行项、下一步。
12. 实现状态：未开始/实现中/代码齐备/需修复。验证状态：未执行/静态核对/运行通过/运行失败。两列独立，不把静态检查当测试通过。
13. 每次只讲 3 个关键决策，追一条请求，说明一个失败点；5–10 分钟随实现进行，提问不作为阻塞开发的考试。
14. 版本冲突核对锁文件与官方资料，禁止使用猜测 API；不追逐新版本。
15. 接口更改先改 schemas/openapi.yaml、JSON Schema 与共享样例，再更新 Go/Python/TS 消费方。
