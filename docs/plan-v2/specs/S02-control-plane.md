# S02：后台配置与前台能力目录

时间：D2。前置：S01。

## 目标
一次完成模型、Skill、MCP、用户管理的后端与页面，使后台保存的配置能够进入前台。

## 实施任务
- 按 UI_SPEC 实现 /admin/models、skills、mcp、users 的真实列表/表单/启停，写管理员审计。
- 首先按 [决策 005](../../decisions/005-model-access.md) 同步 JSON Schema/OpenAPI/共享样例及 Go/Python/TS 生成消费者；新增协议、受控协议选项、可选平台标识、能力与输出上限配置，再实现 API/数据库/UI。
- 模型配置支持多个同协议模型、默认项与 credential_ref；按协议接入，DeepSeek 为首个配置和验收实例，平台不参与适配器选择。部署 origin/path 与凭据别名绑定，服务端拒绝未知协议/协议选项/不支持的模式，仅展示凭据是否配置。
- catalog 隐去连接参数与凭据别名；resolve 验证本轮能力匹配，返回冻结快照。配置检查不调用模型，真实聊天/流式/工具状态初始为未验证，配置 revision 变化使历史验证失效。
- Skill 新增、编辑 Markdown、分类、revision；前台 /app/skills 可浏览并保存个人启用偏好。
- Backend 提供 catalog 与 resolve/validate capabilities，三端消费同一份快照；新运行使用最新配置。
- MCP 连接 CRUD（删除用禁用）；Runtime 实现真正 SDK 初始化/list_tools，Backend 存储发现结果，工具默认禁用，schema 变化撤回启用。
- 自建 demo-mcp 提供 lookup_demo_order，仅合成数据；支持可识别的无匹配、连接失败与超时。只允许白名单地址，重定向不得绕过。
- 模型/工具/配置表单并发修改使用 revision；禁用与错误状态可见。
- 用户创建普通账号、禁用接口与页面；唯一管理员不能禁用。

## 完成与验收条件
- 后台创建 Skill 后前台可见；编辑增加版本；权限不足服务端拒绝。
- MCP 显示“配置已保存”和“协议探测结果”不同状态；未探测不显示已连接。
- 发现工具不会自动授权；同名远端工具有稳定命名空间。
- Key 缺失不阻止其余配置开发；真实模型验证未授权则不执行。
- 准备 A02–A06 验证入口，协议未实际运行就标未验证。
