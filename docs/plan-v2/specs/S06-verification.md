# S06：分层验收与故障修复

时间：D6。前置：S05；执行验证需明确授权。

## 目标
把可演示代码转成有证据的产品；测试未授权时准备全部入口并如实标待执行。

## 实施任务
- 完成 ACCEPTANCE A01–A27 的脚本与有价值用例，使用独立验证数据库/卷/Compose project；启动前检查目标。
- Mock 模式只替换模型，真实 MCP 握手、工具准入、审批、数据库与文件均不替换。
- 授权后先基础登录配置，再聊天派发，再审批恢复，再资料和 UI；先修当前失败再推进。
- 对重复批准、并发启动、提交后断线、配置撤销、等待点重启实施可复现故障注入。
- 覆盖生成完成前正文可见、正文块重连去重、完成全文收敛、中途失败、订阅配额与慢连接；A27 验证配置默认值下行为，不扩展为生产压测项目。
- 浏览器验收桌面和窄屏，尤其侧栏、完整参数审批、错误态、文件下载与前后台配置同步。
- 真模型只在给定次数/预算内验证 A24，报告与 Mock 分开。
- docs/acceptance-report.md 每项记录命令、时间、模式、版本、结果、脱敏证据、已知限制。
- 不以服务启动成功替代全链通过，不删除失败用例；修复后仅复验相关范围与必要主链。

## 完成与验收条件
- A01–A27 每项有状态，未执行不填通过。
- 一套清晰的 verify-mock 入口，可由用户或 CI 触发。
- 无旁路、假 MCP、假下载和静默 Mock 降级。
- 未授权/无 key 不阻塞无关代码交付，但真实链路如实待验收。

## 交付记录
更新 TASKS.md、docs/evidence/S06.md；列出真实文件、接口、迁移、已执行动作、未执行验证、下一任务接入点。所有代码由 AI 编写。

## 随实现讲解
选一个实际失败，说明从 UI、request_id、submission、canonical event 到业务结果的定位路径。

## 可直接下发
阅读共同规则、架构、契约和 UI_SPEC，核对前置后只完成本 S06。保持独立三端与冻结首版范围，不主动启动子代理。默认不执行测试或真实模型，准备验收入口并标明状态；已明确授权的动作按原范围继续。不要要求用户手写，不以讲解阻塞下一阶段。
