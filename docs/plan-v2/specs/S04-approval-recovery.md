# S04：审批、幂等、取消与恢复

时间：D4。前置：S03。

## 目标
形成可核查的写操作闭环，并处理拆服务后的提交窗口。

## 实施任务
- Runtime 创建稳定提案，绑定 execution_id/run/user/tool/args_hash/revisions/expires_at；唯一约束防节点重跑重复建提案。
- approval 节点只准备提案并 interrupt；图等待点确实持久化后才发布 WAITING_APPROVAL。
- Backend decision API 认证归属、拉取提案、检查期限与配置，条件插入不可变决定；重复同决定幂等、冲突409。
- 通过决定命令或显式 resume 驱动原图，Runtime 从 Backend 取决定再验证；客户端不能提交图状态/工具结果。
- 实现 create_demo_ticket provider：逻辑网关调用 Backend 内部事务接口，写工单与原业务结果；run/execution 唯一约束，参数冲突明确错误。
- 业务响应丢失通过 execution_id 查询核查；不可达标 UNKNOWN，不盲重放。
- Runtime 启动核对 interrupt/提案证据，修复 checkpoint 已存但 WAITING 未发布窗口；不能确认的在途运行 INTERRUPTED。
- Backend 持久取消，Runtime 协作收敛；业务事务再次校验取消、决定与相关配置。拒绝/到期/配置失效均明确终态并释放 thread。
- Web 审批卡完整参数、批准/拒绝、状态与恢复入口；管理员 Run 列表显示安全原因。
- 添加默认关闭的内部故障注入配置/验证入口；不向公共 API 暴露任意改状态。

## 完成与验收条件
- 未批准/拒绝/过期/配置禁用不写工单。
- 重复/并发批准只有一张工单；参数变化不能借用旧批准。
- 等待重启、批准已记但未恢复、业务提交后响应丢失均按契约表现。
- 取消不声称撤回已成功写入；UNKNOWN 与明确失败分开。
- 准备 A11–A17，默认不执行；记录每种窗口的预期和实际证据状态。
