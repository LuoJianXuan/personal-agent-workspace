# Agent 网页工作区：5–7 天开发任务包 V2

日期：2026-11-03。状态：Day 1–Day 3 已完成对应范围验收，见 [S03 报告](../evidence/S03.md)；Day 4–Day 7 尚未完成。

## 目标与执行约束

在 5–7 天内实现可部署的个人 Agent 产品：React 网页用户工作区 + 网页管理控制台 + Go Backend + 独立 Python Agent Runtime。AI 编写全部代码；用户通过体验、请求追踪和简短讲解学习，不要求手写，不增加数周学习阶段。

D1–D5 完成全部首版功能代码与集成，D6–D7 取得验收证据、修复并交付。第 5 天只有实际运行成功才能称为闭环；未运行只能标“代码齐备”。本计划按连续冲刺编排，不对环境、模型额度和修复时间作保证，不用缩成单体或删掉后台应付期限。

## 产品定位

参考 LUXTRACE 的网页工作区交互模式，以及灵机 AI 的控制面/运行面职责。用户已确认参考网站由当前灵机 AI 同源代码改造而来。浏览器检查只确认页面，不等于验证网站内部架构或运行能力。

首版是通用对话工作区：可切换模型、选择技能、引用资料、调用 MCP 工具、确认写操作、查看结果与产物。订单建单只是审批演示案例，不能成为唯一产品流程。

本任务包默认用于独立个人项目，参考现有仓库的职责与接口思想，重新实现精简版本；不在公司仓库直接重构，不自动复制公司代码、品牌、数据、提示词和凭据。若日后明确选择授权派生仓库，应单独记录可复用范围，本包不假定已经获得资产复制许可。

## 交付构成

1. 一个 React 工程，两套布局：用户工作区 /app 与管理控制台 /admin。
2. Go Backend：认证、配置、资源归属、会话入口、命令派发、文件、审批决定、管理审计。
3. Python Runtime：LangGraph 主循环、模型访问、逻辑工具网关、checkpoint、运行事件。
4. PostgreSQL：backend 与 runtime 两个 schema、独立数据库角色；同一实例不代表可跨服务读写表。
5. 自建只读 MCP 演示服务；真实初始化、发现和调用。
6. 本地受控文件存储卷，仅 Backend 访问，通过鉴权 API 上传下载。
7. Docker Compose 与 Windows PowerShell、Makefile 开发入口。
8. 契约、验收脚本、脱敏证据、演示说明。

## 首版能力

| 用户工作区 | 管理控制台 | Runtime |
| --- | --- | --- |
| 登录、会话列表、改名、连续对话 | 管理员/普通用户，创建与禁用演示用户 | 单主 Agent，多轮历史装配 |
| 正文增量与流式状态、最终 Markdown、停止运行 | 模型新增、修改、启停、默认模型 | 一个 OpenAI-compatible 协议适配器 |
| 每轮模型与最多 3 个 Skill 选择 | Skill 新增、编辑正文、启停、revision | 消费能力快照，工具入口最终复核 |
| 附件与资料库、预览和下载 | MCP 连接配置、发现工具、启停工具 | Streamable HTTP MCP，参数和结果校验 |
| 工具卡片、审批、等待点恢复 | Run 查询、执行记录、审批状态、审计 | checkpoint、审批中断恢复、幂等 |
| 本轮产物面板，Markdown 报告 | 文件元数据与状态查看 | 受控文本读取、CSV 统计、报告交付 |
| 一个可用的数据分析场景入口 | 场景使用固定模板，不另做编辑器 | CSV 数据由固定工具计算，模型解释 |

功能详细限制以 SCOPE.md 为准。用户端和后台都是真实 API 页面，不用占位按钮冒充实现。
